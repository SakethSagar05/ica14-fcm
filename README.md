# ICA 14 – Firebase Cloud Messaging in Flutter

**Course:** CSC 4360 Mobile App Development · **Student:** Saketh Sagar Kokkireni
**Platform:** Android (one target) · **Stack:** Flutter, `firebase_core` 4.x, `firebase_messaging` 16.x

A Flutter app that receives FCM messages and uses the custom data payload to change the
visible title and image. It shows which handler ran, how many messages this launch has
handled, and the last message ID, so each test produces fresh, checkable evidence.

## Payload contract

| Key | Allowed values | Effect |
|---|---|---|
| `action` | `update_ui` | Required; anything else is rejected |
| `asset` | `default`, `promo` | Selects `assets/images/default.png` or `promo.png` |

A missing or unsupported value is rejected with an on-screen diagnostic; the previous
title/image are kept and the app does not crash (receipt metadata still updates).

## Where things are

| Requirement | Where |
|---|---|
| Firebase initialised before `runApp()`; top-level `@pragma('vm:entry-point')` background handler registered first | `lib/main.dart` |
| `FCMService`: `onMessage`, `onMessageOpenedApp`, `getInitialMessage()`, permission request, token + token refresh, cancellable subscriptions, dispose guard | `lib/fcm_service.dart` |
| Payload → UI with an allow-list of assets, handler/count/message-ID panel, rejection diagnostic | `_HomePageState._handleMessage` in `lib/main.dart` |
| One-shot setup (platform folder, packages, Android config, `flutterfire configure`, analyze, debug build, git) | `tools/setup.sh` |
| adb helper: copy token to clipboard, screenshots, device/permission info | `tools/fcm_helper.sh` |
| Evidence | `docs/screenshots/`, `docs/device.txt`, `docs/env.txt` |

### Lifecycle handlers

| State | Event | Handler | Can update UI? |
|---|---|---|---|
| Foreground | Message received | `FirebaseMessaging.onMessage` | Yes |
| Background | User taps the notification | `onMessageOpenedApp` | Yes (app returns to foreground) |
| Terminated | Notification tap cold-starts the app | `getInitialMessage()` | Yes, after init |
| Background/terminated | Message delivered to Dart for background work | `onBackgroundMessage` (top-level) | **No** – separate isolate, no widget tree; logs only |

A registration token addresses one app installation; it is not a user identity or an
authorization decision. Nothing sensitive is sent in payloads.

## Setup

Prerequisites: Flutter SDK, Android SDK with a **Google Play** emulator image (or a phone
with USB debugging), Node.js, and access to the Firebase project.

```bash
bash tools/setup.sh            # defaults to Firebase project ica13-auth
flutter run
```

`lib/firebase_options.dart` and `android/app/google-services.json` are generated by
`flutterfire configure` and are not committed; re-run `tools/setup.sh <your-project-id>`
to regenerate them for another Firebase project.

## Testing (T1–T4)

Valid payload (Firebase Console → Messaging → New campaign → Notifications; custom data
under *Additional options*; then **Send test message** to the current token):

```json
{
  "notification": { "title": "New promotion", "body": "Switch the screen to the promo asset" },
  "data": { "asset": "promo", "action": "update_ui" }
}
```

T4 invalid variant: `asset = unknown` (keep `action = update_ui`).

| Test | Steps | Expected |
|---|---|---|
| T1 | App visible, send | `Last handler: onMessage`, promo image, title "New promotion" |
| T2 | Home button, send, tap notification | `onMessageOpenedApp`, count +1 |
| T3 | Swipe app away in Recents (not force-stop), send, tap notification | `getInitialMessage`, count = 1 |
| T4 | App visible, send `asset=unknown` | `onMessage`, count +1, "Rejected payload…" diagnostic, previous image kept |

Results, device/permission details and the reflection are in the submitted reflection document.
